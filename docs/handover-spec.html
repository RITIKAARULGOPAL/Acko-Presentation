01How your files are used

The presentation is a single interactive HTML page, presented live with a clicker or browsed by the client on their own. It does not paste in screenshots of drawings. It reads your drawing data and builds every view from it.

Because everything is read from the files, the numbers in the presentation (areas, desk counts, route lengths, seats) always match the drawings. A design change later only needs fresh exports with the same names. The trade-off is that the files need some preparation, which is what this document sets out.

2.4Drawing rules for every PRES layer

  1. Closed means closed. Draw with PLINE and finish with C (Close), or set Closed = Yes in Properties. A polyline whose last point only touches its first point is not closed. Check with LIST; it must say "Closed".
  2. Polylines only (LWPOLYLINE). No splines, regions, hatches or lines joined by eye. Arcs inside boundary polylines are fine; fire routes use straight segments only.
  3. One label per shape, inside the shape. The text's insertion point must sit inside its polyline. We match each label to the polygon that contains it.
  4. No blocks. Draw PRES geometry loose in model space, never inside blocks or groups.
  5. No overlaps between shapes on the same layer.
  6. Fastest way to trace: BOUNDARY (BO) with Object type = Polyline creates a closed polyline when you click inside an enclosed area. Then move the result to the PRES layer.

2.5Neighbourhood boundaries and areas

The neighbourhood, Town Square, street, core and stair polygons together tile the floor plate. Draw them so every part of the plate is covered once:

  • Neighbourhood edges run along the edge of a street, not its centre line. Streets are polygons of their own.
  • Polygons may share edges. They must not overlap.
  • Small gaps such as wall thicknesses are fine. We report what's left as "walls and other".

From these polygons the presentation calculates each neighbourhood's area in sq ft, the area split (neighbourhoods, shared zen rooms, Town Square, loop and lanes, core), and which furniture and rooms belong to which neighbourhood.

If the boundaries aren't final yetDraw only PRES-STREET, PRES-CORE, PRES-STAIR and PRES-TS. We derive the neighbourhoods as the parcels left between them, which is the story the presentation tells, and send you a marked-up plan to confirm names and edges.

2.6Fire escape routes

Each polyline on PRES-FIRE-ROUTE becomes an animated escape route. The line draws itself from its start, keeps flowing towards the exit, and ends in an arrowhead at the door. Its length is measured from the drawing and shown in metres at the start point, with a check against the permitted travel distance.

  1. Draw from the far point to the exit. The first vertex is the farthest occupied point of the zone. The last vertex sits exactly on the exit door, at the same point as the EXIT text.
  2. Follow the real clear path along aisles, lanes and the loop. Put a vertex at every turn. No diagonal short-cuts through furniture or walls.
  3. At least one route per zone: the longest route for each neighbourhood and for the Town Square. Add more if the fire plan shows them.
  4. Straight segments only.
  5. Tell us the limit: the permitted travel distance and its basis (for example NBC 2016 Part 4, and whether the floor is sprinklered). Each route is checked against it.
Also sendThe fire consultant's egress plan as a PDF, if one exists. We cross-check the routes against it.

The loop. The main corridor is one endless loop: the corridors on both sides of the core join at each end. Draw its centre line on PRES-LOOP as one closed polyline that runs round the whole loop, with arcs or a short chamfer at the corners. The presentation draws it in and runs dots round it. Its length is shown in metres.

03SketchUp axo exports

The axo is shown as a set of images from one fixed camera. Each export has different tags switched on. Because every image lines up exactly, the presentation can stack them, build the axo up layer by layer, pull the layers apart for the exploded view, and highlight one neighbourhood at a time.

Why images and not the .skp fileSketchUp files can't be opened outside SketchUp. Images from a fixed camera look exactly like your model, stay light enough for a laptop, and line up perfectly with each other. A 3D export is an optional extra (3.7).

3.1Model set-up and tags

If the model was built on the imported CAD at the same origin and scale, keep it that way; it makes the alignment exact. Organise the model as groups with two kinds of tags: a zone tag on each zone group, and a category tag on the groups inside it.

Model
├─ Shell                    group · tag SHELL       slab, columns, core, façade
├─ N1 Indiranagar           group · tag NB-N1
│  ├─ floor finishes        group · tag FLOOR       carpet, rugs, raised areas (optional)
│  ├─ partitions and glass  group · tag WALLS       walls, glass, doors, booths' shells
│  ├─ furniture             group · tag FURNITURE   all loose and fixed furniture, planters
│  └─ ceiling               group · tag CEILING     rafts, baffles, lights (optional)
├─ N2 … N6                  same pattern · tags NB-N2 … NB-N6
├─ Town Square              group · tag TS          same four sub-groups
├─ Streets                  group · tag STREET      circulation floor finish (optional)
└─ Reference markers        group · tag REF         4 red markers at floor level (3.5)
  • Tag groups and components. Keep raw edges and faces Untagged.
  • Nothing loose inside a zone group: every item sits in its FLOOR, WALLS, FURNITURE or CEILING sub-group.
  • SketchUp hides an object when its own tag or any parent's tag is hidden. That is what lets one model give every export in 3.4 just by switching tags.

Why parallel projectionA perspective camera distorts each part of the image differently, so separate layer images and CAD overlays could never line up. Parallel projection keeps every floor point in a fixed spot and keeps verticals vertical. That makes the stacking, the plan-to-axo move and the exploded view exact.
The most common mistakeThe export height follows the window's shape. Opening a tray or resizing the window between exports changes the framing, and the images no longer line up. Check that every PNG has exactly the same pixel size.

3.5Reference markers (alignment)

For the plan-to-axo animation, the CAD plan has to land exactly on the axo floor, carrying the neighbourhood colours, fire routes, room click areas and labels with it. Four markers make that exact.

  1. In CAD, place REF-1 to REF-4 on PRES-REF: three at outer corners of the floor plate and one at a column far from them. The four must not lie on one line.
  2. In SketchUp, at the same four points, place a small marker (a 300 mm disc or cube, pure red #FF0000, at floor level) on tag REF. If the model sits on the CAD at the same origin, snap to the same points.
  3. Export axo-ref.png with only REF visible, shadows off.
Why four pointsIn a parallel projection, the floor plan and its image in the axo are related by one fixed stretch, skew and shift. Three known points pin that relationship down; the fourth confirms it. With it, anything drawn on the CAD plan lands in the right place in the axo.

3.6Neighbourhood close-ups for the deep dives

Each deep dive shows a neighbourhood's plan next to its axo. We crop the axo-zone-* images, which is why the exports are 6000 px wide: a single neighbourhood cropped out still stays sharp on a large screen. If you prefer a closer camera per neighbourhood, export each from its own scene with its own reference image, following the same rules: axo-n1-close.png and axo-n1-close-ref.png, and so on.

3.7Optional: 3D model

For a version the client can orbit, also export the model as COLLADA (.dae) through File → Export → 3D Model, or as .glb through a glTF exporter extension. Keep the same tags, embed textures and aim for under 50 MB. This is an add-on; the image set above is the main deliverable.

3.8SketchUp checklist

  • Camera set to Parallel Projection
  • Scene PRES-AXO saved; camera never moved after
  • Tags: SHELL, FLOOR, WALLS, FURNITURE, CEILING, STREET, NB-N1…N6, TS, REF
  • Nothing loose inside zone groups
  • Sky, ground and fog off; same style throughout
  • Shadows on for axo-full only
  • All PNGs 6000 px wide, same height, transparent
  • REF markers at the same points as in CAD
  • File names exactly as in 3.4
  • Window and trays unchanged between exports

04Renders for the click-to-view viewer

Clicking a room in the plan, the axo or a deep dive opens its renders. Each space has a light and a dark version, with a toggle and a slider that wipes from one to the other. The two versions have to line up exactly for the slider to work.

4.1Render rules

  1. Same camera for light and dark: same position, lens and crop. Only materials and lighting change. Save the camera as a view in your render tool (Enscape, V-Ray, D5 or Lumion) and render both versions from it.
  2. Same size for every render: 2400 to 3000 px wide, all in one aspect ratio (16:9 or 16:10).
  3. JPG, quality 85–90, sRGB colour profile.
  4. No text, logos or watermarks baked into the images.
  5. Shared or per neighbourhood: meeting-light.jpg is used by every neighbourhood. To show a different meeting room in one neighbourhood only, add n1-meeting-light.jpg and n1-meeting-dark.jpg.

06How the files become the presentation

Background for the whole team: what happens to each file, so it's clear why the set-up rules matter.

6.1Plan, neighbourhoods and numbers

The DXF is converted into clean vector layers in the presentation's own line weights and colours, readable in both light and dark themes. The PRES polygons become the coloured neighbourhoods, the Town Square and the streets. Areas, the area split, desk and room counts, and each neighbourhood's kit list are calculated from the polygons and the furniture blocks.

The brief sheet sets each neighbourhood's share: the total divided by six, plus any extras you list. The counts from the drawing are compared with that share, cell by cell, and every shortfall is shown with the reason from the sheet. Zen rooms are matched to their pair from the two IDs in their label.

6.2Fire escape routes

Each route polyline draws itself in from its first vertex and then keeps flowing towards its last, ending in an arrowhead at the exit door. Its length is measured along the polyline in metres and checked against the travel-distance limit. In the next step, the routes widen into the loop and lane polygons, and the loop closes into one endless corridor, to show the escape routes becoming the plan's circulation.

6.3Plan to axo, and the exploded view

  1. Plan. The CAD plan with its coloured neighbourhoods, as in the earlier steps.
  2. Onto the axo floor. Using the four reference points, the plan stretches, skews and slides until it sits exactly on the axo's floor. Colours, routes and labels move with it.
  3. Build-up. The SketchUp layers appear in order (shell, floor, walls, furniture) and the hero image axo-full.png settles in.
  4. Exploded. In a parallel projection, lifting a layer in 3D is the same as sliding its image straight up the screen. The layer images separate vertically, with the neighbourhood colours on their own level and a label beside each layer.

Hovering a neighbourhood in the axo dims the others, using its axo-zone-* image. Clicking it opens that neighbourhood's deep dive.

6.4Deep dives and renders

Each deep dive shows the neighbourhood's plan beside its cropped axo-zone image. Numbered markers for each kit item are placed on both from the CAD positions, through the same alignment. Clicking a room (from its PRES-ROOM polygon) or a marker opens the light and dark renders for that room's keyword.

07Handover and next steps

What happens after the files are shared.

  1. Share the folder laid out as in 1.1, as a zip or a drive link.
  2. Automatic checks. We test the DXF (closed shapes, labels inside shapes, overlaps, route end points on exit doors, units) and the PNGs (identical sizes, transparency, reference markers found).
  3. Alignment check. We send back one page showing your CAD plan, with neighbourhoods and routes, laid over your axo, plus a short list of anything missing or unclear.
  4. Build. Once you confirm, the real drawings replace the sample data in the presentation.
  5. Changes later. Re-export with the same file names and settings, and the presentation picks up the changes.
Quick self-check before sendingOpen acko-layout.dxf in DWG TrueView or AutoCAD and confirm the PRES layers show. Open any two PNG exports side by side and confirm they have the same pixel size and that a column sits on exactly the same pixel in both.
